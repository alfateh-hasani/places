# سيناريو الحجز - شرح تفصيلي (Booking Lifecycle)

## نظرة عامة

نظام الحجز في المنصة يدعم قنوات متعددة (ويب، موبايل، Airbnb، OwnerRez...) ويمر الحجز بسلسلة من الحالات المتغيرة بحسب الأحداث. فيما يلي الشرح الكامل.

---

## أولاً: حالات الحجز (Booking Statuses)

| الحالة | القيمة | الوصف |
|--------|--------|-------|
| معلق | `pending` | الحالة الأولية بعد إنشاء الحجز، بانتظار الدفع |
| مؤكد | `approved` | تم استلام الدفع وتأكيد الحجز |
| محجوز | `booked` | الحجز نشط والضيف في طريقه أو قادم قريباً |
| منتهي | `finished` | انتهت مدة الحجز والضيف غادر |
| ملغى (من الإدارة) | `canceled` | ألغت الإدارة الحجز |
| ملغى (من الزبون) | `customer_canceled` | ألغى الزبون الحجز بعد الدفع (يُنشئ طلب استرداد) |
| مرفوض | `rejected` | رفضت الإدارة الحجز |

## حالات الدفع (Payment Statuses)

| الحالة | القيمة | الوصف |
|--------|--------|-------|
| بانتظار الدفع | `pending` | لم يتم الدفع بعد |
| مدفوع | `paid` | تم الدفع بنجاح |
| فشل الدفع | `failed` | فشلت عملية الدفع |

## حالات كود الدخول (Passcode Statuses)

| الحالة | القيمة | الوصف |
|--------|--------|-------|
| بانتظار التوليد | `pending` | لم يُولَّد الكود بعد |
| تم التوليد | `generated` | تم توليد كود الدخول بنجاح على القفل الذكي |
| فشل التوليد | `failed` | فشل توليد الكود |
| مجدول للإعادة | `retry_scheduled` | تمت جدولة إعادة المحاولة |

## حالات الاسترداد (Refund Statuses)

| الحالة | القيمة | الوصف |
|--------|--------|-------|
| بانتظار المراجعة | `pending` | طلب الاسترداد بانتظار مراجعة الإدارة |
| موافق عليه | `approved` | وافقت الإدارة على الاسترداد |
| مرفوض | `rejected` | رفضت الإدارة طلب الاسترداد |

```
           │
           ▼

           │
           ▼
```

```
           │
   ┌───────▼────────┐
   │ فحص الشروط    │

   │ - ليست خارجية؟│

           ▼

           │
           ▼

```

```

           │
           ▼

           │
```

## ثامناً: المهام المجدولة (Scheduled Jobs/Commands)

| الأمر | المهمة | التكرار |
|-------|--------|---------|
| `DeletePendingBookings` | حذف الحجوزات التي بقيت `pending` أكثر من 10 دقائق بدون دفع | دورياً |
| `CheckBookingsWithoutPasscodes` | كشف الحجوزات المؤكدة بدون كود دخول | دورياً |
| `RetryFailedPasscodes` | إعادة محاولة توليد الأكواد الفاشلة | دورياً |
| `OwnerRez\SyncBookingsCommand` | مزامنة الحجوزات مع OwnerRez | دورياً |

```

                    │    pending      │ ←── الحالة الأولية
                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
              ▼              ▼              ▼
         ┌─────────┐   ┌──────────┐  ┌──────────┐
         │ approved│   │ canceled │  │ rejected │

     ┌────────┼────────────────────┐
     │        │                    │
     ▼        ▼                    ▼
```

## ملاحظات مهمة

- **الحالات النهائية** (لا رجعة منها): `finished`, `canceled`, `rejected`
- **سياسة الإلغاء**: لا يمكن الإلغاء إلا قبل 24 ساعة من الدخول (قابل للضبط)
- **الحجوزات الخارجية** (Airbnb, OwnerRez): تُنشأ مباشرة بحالة `approved + paid` وتتجاهل تدفق الدفع المحلي
- **حجوزات `pending` المهجورة**: تُحذف تلقائياً بعد 10 دقائق عبر `DeletePendingBookings`
- **فشل الكود**: لا يؤثر على حالة الحجز (`approved` تبقى كما هي)، لكن `passcode_status` يتغير بشكل مستقل
